# Интеграция MatrixZeroAnalyzer

## Вариант
Вариант 6. Сохраняется задача из ЛР 1–2:
подсчёт нулей относительно диагоналей квадратной матрицы.
Стратегия — Т-образная. Протокол — обмен через бинарный файл.
Бинарный обмен будет реализован на уровне 2.

## Стратегия и обоснование
Сначала реализован простой сквозной сценарий через все слои:
ввод, анализ, формирование результата.
Затем расширены проверки входных данных и граничных случаев.
Это позволяет проверить совместимость всей цепочки,
после чего последовательно расширять возможности системы.

## Модули
- input_module.py — проверка и нормализация матрицы.
- matrix_zero_analyzer.py — подсчёт нулевых элементов.
- report.py — формирование текстового результата.
- integration.py — управление цепочкой вызовов.

## Схема интеграции
Матрица
  -> create_matrix_payload(matrix)
  -> словарь входных данных
  -> analyze_payload(payload)
  -> словарь результатов
  -> преобразование в кортеж четырёх счётчиков
  -> format_report(counts)
  -> текстовый результат.

Последовательность выполняется функцией run_pipeline.
На уровне 1 используются прямые вызовы функций.
Все модули доступны, поэтому заглушки не потребовались.
Демонстрационный запуск выполняет функция main.

## Интерфейсы
create_matrix_payload принимает квадратную числовую матрицу.
Возвращает protocol_version, matrix_size и matrix_data.

analyze_payload принимает словарь входных данных.
Возвращает dim, zeros_above_main, zeros_below_main,
zeros_above_secondary и zeros_below_secondary.

format_report принимает кортеж из четырёх счётчиков.
Порядок: выше главной, ниже главной,
выше побочной, ниже побочной диагонали.
Результат — строка с текстовым отчётом.

## Обработка ошибок
Модуль ввода отклоняет пустую и неквадратную матрицу,
строковые и логические элементы с исключением ValueError.
Функция main перехватывает ValueError, TypeError и KeyError
и выводит сообщение об ошибке.

## Уровень 2 — бинарный обмен

Полная цепочка:
create_matrix_payload -> write_payload -> бинарный файл
-> read_payload -> analyze_payload -> map_analysis_result
-> format_mapped_report.

Цепочкой управляет run_file_pipeline из binary_integration.py.
Файл отделяет этап подготовки данных от этапа их обработки.
При демонстрационном запуске файл размещается во временном каталоге.

### Структуры данных
Ввод: словарь с версией протокола, размером и матрицей.
Транспорт: бинарный заголовок и последовательность чисел.
Анализ: словарь с размером и четырьмя счётчиками.
Вывод: словарь с переименованными полями, затем текстовая строка.

### Формат бинарного файла

Порядок байтов: little-endian.
Заголовок struct: <4sBI. Размер заголовка: 9 байт.

| Смещение, байт | Размер, байт | Содержимое |
| --- | --- | --- |
| 0 | 4 | Сигнатура MZA1 |
| 4 | 1 | Версия протокола: 1 |
| 5 | 4 | Размер квадратной матрицы n |
| 9 | 8*n*n | Элементы float64 по строкам |

Допустимый размер матрицы: от 1 до 1000.
Общий размер файла: 9 + 8*n*n байт.
Лишние или недостающие байты считаются ошибкой.
Строковая версия 1.0 в словаре соответствует байтовой версии 1.

### Сопоставление полей анализа и вывода

| Поле анализа | Поле вывода | Тип |
| --- | --- | --- |
| dim | dimension | int |
| zeros_above_main | main_diag_upper | int |
| zeros_below_main | main_diag_lower | int |
| zeros_above_secondary | sec_diag_upper | int |
| zeros_below_secondary | sec_diag_lower | int |

Преобразование выполняет map_analysis_result.
Числовые элементы входной матрицы нормализуются в float.
После чтения файла восстанавливается входной словарь.

### Пример входа и результата

Вызов: run_file_pipeline([[1, 0], [0, 1]], path).
Вход: матрица 2x2, версия протокола 1.0.
Файл: 41 байт.
Результат: текстовый отчёт для матрицы 2x2.
Счётчики: выше главной — 1, ниже главной — 1,
выше побочной — 0, ниже побочной — 0.

Запуск демонстрации: python -m src.binary_integration.
Для матрицы 3x3 получен файл 81 байт и счётчики 3, 3, 2, 2.
