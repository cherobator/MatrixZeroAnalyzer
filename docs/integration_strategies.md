# Сравнение стратегий интеграции

| Стратегия | Преимущества | Недостатки | Когда выбирать |
| --- | --- | --- | --- |
| Нисходящая | Рано проверяется управление системой | Требуются заглушки нижних модулей | Важны интерфейс и управляющая логика |
| Восходящая | Рано проверяются базовые операции | Нужны драйверы, поздно видна система целиком | Критичны вычисления и инфраструктура |
| Сэндвич | Верхние и нижние слои проверяются параллельно | Сложнее согласовать средний слой | Крупные многослойные системы |
| Риск-ориентированная | Рано выявляются наиболее опасные проблемы | Требует оценки рисков | Сложные внешние зависимости |
| Функционально-ориентированная | Быстро проверяются законченные функции | Возможны повторные изменения общих модулей | Разработка по пользовательским сценариям |
| Т-образная | Рано проверяется сквозное взаимодействие | Первый сценарий не охватывает все случаи | Важна совместимость нескольких слоёв |

## Способ объединения модулей

| Способ | Преимущества | Недостатки | Применение |
| --- | --- | --- | --- |
| Одновременный | Простая организация для малого проекта | Трудно локализовать ошибки взаимодействия | Небольшое число простых компонентов |
| Инкрементный | Ошибки выявляются после небольших изменений | Требуются промежуточные проверки | Постепенное развитие системы |

## Выбор для MatrixZeroAnalyzer
По варианту 6 используется Т-образная стратегия.
Сначала реализован сквозной сценарий ввода, анализа и вывода.
Затем добавлены бинарный транспорт, сопоставление данных,
обработка исключений и автоматические проверки.

Развитие выполнялось инкрементно:
каждое расширение сопровождалось проверками и коммитами.
Т-образная стратегия определяет направление интеграции,
а инкрементный способ — порядок внесения изменений.

Для вычислительной библиотеки была бы удобна восходящая стратегия.
Для системы с нестабильным внешним сервисом целесообразно
начать с риск-ориентированной проверки этого сервиса.
